# cart-pendulum

Проект контроллера классической задачи **inverted pendulum on a cart** с переносом с симуляции на реальный макет и постепенной идентификацией неизвестных параметров.

## С чего начать

- [План проекта и декомпозиция задач](docs/PROJECT_PLAN.md)

Работа строится поэтапно: сначала контракты и воспроизводимая симуляция, затем оценка состояния и базовое управление, после этого — идентификация параметров, hardware-in-the-loop и только потом испытания на реальном макете.

### Текущий инкремент

Уже реализованы:

- валидируемая TOML-конфигурация в `configs/default.toml`;
- общие контракты `State`, `Measurement` и `ActuatorCommand`;
- нелинейная модель с фиксированным шагом и RK4;
- safety supervisor с защёлкиваемым fault-состоянием;
- CSV-лог симуляции и 13 unit/integration-тестов.

Запуск без установки зависимостей:

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python examples/run_simulation.py
```

Последняя команда записывает демонстрационный лог в `artifacts/open_loop_zero_force.csv`. В конфигурации используются только номинальные параметры для симуляции, а не параметры реального макета.

Важное ограничение: отсутствие параметров не решается одной «магической» адаптацией. Нужны измерения, безопасный базовый режим, сбор данных и ограниченная адаптация с возможностью отката.
